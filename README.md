# SQL Faker

Fake user data generator written in PostgreSQL.
All data is generated by SQL functions. The Streamlit app only calls them and shows the result.

Live app: https://sql-faker.streamlit.app

## Usage

```sql
SELECT * FROM faker_users('en_US', 42, 0);   -- batch 0: users 1-10
SELECT * FROM faker_users('en_US', 42, 1);   -- batch 1: users 11-20
SELECT * FROM faker_users('de_DE', 7, 0, 50); -- 50 German users
```

Arguments: locale (`en_US` or `de_DE`), seed, batch index, batch size (default 10).
The same arguments always return the same users.

Each user has: full name, gender, address, latitude, longitude, height, weight, eye color, phone, e-mail.

PostgreSQL procedures cannot return rows, so the stored procedures are written as functions.

## Database

- `locales` - one row per locale with its parameters (average height for men and women).
- `words` - all lookup lists in one table, split by `locale` and `category`
  (first names, last names, titles, streets, cities, eye colors, and the format templates).
  A new locale is just new rows, no new tables or code.
- `word_counts` - size of each list, so a random pick does not count rows every time.

The lists are big enough for more than a million different users
(about 700 first names x 1 000 last names for `en_US`, 2 000 x 400 for `de_DE`, plus format variations).

## Functions

| Function | Returns |
|---|---|
| `faker_random(key, stream)` | uniform number in [0, 1) |
| `faker_random_int(key, stream, min, max)` | integer from min to max |
| `faker_normal(key, stream, mean, sd)` | number from a normal distribution |
| `faker_pick(locale, category, u)` | random value from a list, all values equally likely |
| `faker_pick_weighted(locale, category, u)` | random value from a list, using the `weight` column |
| `faker_digits(key, stream, pattern)` | pattern with `#` replaced by a digit 0-9 and `%` by 1-9 |
| `faker_ascii(text)` | name without accents, for e-mails (`ü` -> `ue`) |
| `faker_person(locale, key)` | gender, first name, last name, full name |
| `faker_street(locale, key)`, `faker_city(locale, key)` | street name, city name |
| `faker_address(locale, key)` | full address |
| `faker_geo(key)` | latitude, longitude |
| `faker_physical(locale, key, gender)` | height, weight, eye color |
| `faker_phone(locale, key)`, `faker_email(locale, key, first, last)` | phone number, e-mail |
| `faker_users(locale, seed, batch, batch_size)` | one batch of users (main function) |

## Algorithms

**Reproducible random numbers.** Every user has a key `locale|seed|batch|index`, for example `en_US|42|0|3`.
A random number is `md5(key + '|' + stream)`, where the stream is the name of the value (`height`, `last`, ...).
The first 52 bits of the hash divided by 2^52 give a number in [0, 1).
The same input always gives the same number, so the same user can be generated again at any time.

**Normal distribution.** Box-Muller transform: for two uniform numbers u1 and u2,
`sqrt(-2 ln u1) * cos(2 pi u2)` is normally distributed. It is used for height,
and for BMI: weight = BMI x height², so height and weight stay realistic together.

**Points on a sphere.** Longitude = `360u - 180`. Latitude = `asin(2v - 1)`.
A uniform latitude would put too many points near the poles, because circles of latitude get shorter there.
With `asin` each part of the sphere gets points in proportion to its area.

**Names, addresses, phones, e-mails.** Built from templates stored in `words`, for example
`{title} {first} {last}`, `{number} {street}, {city}, {region} {zip}` or `(%##) %##-####`.
A template is picked with weights, then the placeholders are filled with random values.
To change how names look, edit or add templates. No code changes are needed.

## Benchmark

10 000 users in one query on the free Neon plan: about **1 900 users/second** (`en_US`) and **1 970 users/second** (`de_DE`).
Run with `python benchmark.py "<connection string>"`.

## Setup

`python setup_db.py "<connection string>"` runs `schema.sql`, `seed.sql` and `functions.sql`.

`seed.sql` is made by `build_seed.py` (needs `pip install faker`).
The word lists come from the open-source Faker library. Only the lists are used, all generation is done in SQL.
